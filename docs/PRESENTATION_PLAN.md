# Swiftly — план презентації (11 слайдів)

Відповідність слайдів вимогам кафедри після оновлення `Swiftly_Presentation.odp`.

| № | Вимога плану | Зміст у презентації |
|---|--------------|---------------------|
| 1 | Титульний | Назва роботи, ПІБ, керівник, кафедра, рік, стек |
| 2 | Актуальність і мета | Проблема, об'єкт, предмет, мета, завдання |
| 3 | Аналоги | Порівняльна таблиця Shopify / KeyCRM / B2B / Swiftly |
| 4 | Постановка задачі | Функціональні/нефункціональні вимоги, UC, ролі |
| 5 | Архітектура | SPA + API + PostgreSQL, 8 таблиць |
| 6 | Технічне рішення 1 | Замовлення, транзакції, модель даних, ендпоінти |
| 7 | Технічне рішення 2 | JWT, RBAC, модерація дропшипера |
| 8 | Демо (B2C) | Каталог, кошик, чекаут (+ скриншоти) |
| 9 | Демо (B2B) | Кабінети дропшипера, постачальника, адміна (+ скриншоти) |
| 10 | Тестування + висновки | Сценарії тестів, короткі висновки |
| 11 | Подяка | Подяка, метрики проєкту |

## Що виправлено відносно початкової версії

- **React 19 → React 18** (фактичний стек проєкту)
- **6 → 8 таблиць** (додано `categories`, `cart_items`)
- **18 → ~29 REST-ендпоїнтів**
- **Swiflty → Swiftly**
- Додано **об'єкт, предмет, мета, завдання**
- Слайд «технологічний стек» перероблено на **вимоги та use cases**
- Додано **модерацію дропшипера**, **тестування**
- Прибрано завищення **«13/13 критеріїв»**

## Резервна копія

Оригінал: `Swiftly_Presentation.odp.bak` (поруч із `.odp`).

## Повторне оновлення

```bash
python3 docs/update_presentation.py
```

## Рекомендації перед захистом

1. Перевірте кафедру в титулі (за потреби замініть «Кафедра комп'ютерних наук»).
2. На слайдах 8–9 переконайтесь, що скриншоти актуальні (модерація дропшипера, видалення товару).
3. Додайте діаграму Use Case вручну на слайд 4 (за бажанням комісії).
